# Поиск и устранение неисправностей

> **Самые частые проблемы:**
> - Не открываются заблокированные сайты на одном устройстве, а на других всё работает? Проверьте DNS на этом устройстве (см. «Диагностика на клиентском устройстве»).
> - В диагностике `FakeIP Status: does not work in browser`? Скорее всего, «Безопасный DNS» в браузере (см. [DNS на клиентах](https://tangenx.github.io/perekop/) — отключите DoH/DoT в браузере.

## Как работает маршрутизация

Маршрутизация **по доменным именам** корректна, только если выполнены **все** условия:

1. **DNS-запросы** клиента (браузер, приложения) идут на роутер с Perekop.
2. **Роутер с Perekop** — шлюз для всего трафика клиента (как минимум для FakeIP `198.18.0.0/15`).
3. **`dnsmasq` на роутере** обрабатывает DNS и пересылает в `127.0.0.42` (включается автоматически, если не активна настройка «Не трогать мой DHCP»).
4. **Xray** запущен, слушает `127.0.0.42:53`, конфиг собран, удалённые списки загружены.
5. **Правила `nftables`** маркируют LAN-трафик и перенаправляют через `tproxy` на `127.0.0.1:1602`.
6. **Внешнее подключение** (прокси-ссылка, аутбаунд или VPN) работоспособно, у роутера есть интернет.

## Диагностика на клиентском устройстве (ПК, смартфон)

### Проверка получения FakeIP

```shell
nslookup fakeip.podkop.fyi
```

Ожидаемо:

```text
Server:     192.168.1.1
Address:    192.168.1.1#53

Name:       fakeip.podkop.fyi
Address: 198.18.x.x
```

- **Ответ другой IP** (например, `64.188.104.86` вместо `198.18.x.x`) — устройство использует сторонний DNS (адрес виден в строке `Server`). Решение — [DNS на клиентах](https://tangenx.github.io/perekop/), отключите DoH.
- **Ответ пустой**, сервер — IP роутера — проблема на стороне роутера. Переходите к «Проверка настроек DNS на роутере».

### Проверка прохождения трафика через Xray

```shell
curl -v https://fakeip.podkop.fyi/check
```

Должна быть попытка подключения к FakeIP (`Trying 198.18.x.x...`) и в конце:

```json
{"fakeip": true, "IP": "XX.XX.XX.XX"}
```

- **`curl` зависает** — трафик не доходит до Xray. Убедитесь, что роутер — шлюз для устройства, а правила nftables работают (см. ниже).
- **`curl` подключается к `198.18.*`, но `"fakeip": false`** — серьёзная проблема в Xray или правилах nftables.

### В терминале хорошо, а в браузере нет?

Если `nslookup` и `curl` в терминале работают, а в браузере ошибка `does not work in browser` — откройте в браузере `https://fakeip.podkop.fyi/check`. Если вернёт `{"fakeip": false, ...}` — включён «Безопасный DNS» в браузере, отключите его (Chrome: **Настройки → Приватность → Использовать безопасный DNS**; Firefox: **Настройки → Приватность → DNS over HTTPS → Off**; Android: **Настройки → Подключения → Приватный DNS**).

### Телевизоры, телефоны без терминала

Откройте веб-интерфейс Perekop (LuCI → Services → Perekop) → «Диагностика».

Если браузера нет:

- Логи dnsmasq: LuCI → Network → DHCP and DNS → вкладка Log → **Log queries**; затем `logread -f -e dnsmasq`.
- Видеть трафик: `tcpdump -i br-lan -nn`.
- Если не видно DNS-запросов от устройства — значит, на устройстве внешние DNS или DoH.

## Проверка настроек DNS на роутере

Откройте SSH на роутере.

### 1. Порты и процессы

```shell
netstat -tanp | grep LISTEN
```

Должны быть строки вида:

```text
tcp  ...  127.0.0.42:53    0.0.0.0:*   LISTEN   xray
tcp  ...  127.0.0.1:1602   0.0.0.0:*   LISTEN   xray
tcp  ...  127.0.0.1:53     0.0.0.0:*   LISTEN   dnsmasq
tcp  ...  192.168.1.1:53   0.0.0.0:*   LISTEN   dnsmasq
```

Это подтверждает: `dnsmasq` принимает DNS на LAN, Xray — на `127.0.0.42`. Если нет — проверяйте конфигурации.

### 2. Конфигурация dnsmasq

```shell
uci show dhcp.@dnsmasq[0]
```

Должны быть:

```text
dhcp.cfg01411c.noresolv='1'
dhcp.cfg01411c.server='127.0.0.42'
```

- `noresolv='1'` — запрещает роутеру использовать внешние DNS в обход Perekop.
- `server='127.0.0.42'` — все DNS-запросы пересылаются напрямую в Xray.

Если настроек нет или в `server` есть другие адреса — вероятно, включена опция «Не трогать мой DHCP». Настройте её вручную.

### 3. Инструменты LuCI и CLI

```shell
/usr/bin/perekop global_check      # полный отчёт (сохранить в .txt для обращения в чат)
/usr/bin/perekop check_xray
/usr/bin/perekop check_fakeip
/usr/bin/perekop check_nft_rules
/usr/bin/perekop show_xray_config
/usr/bin/perekop get_runtime_info
logread | grep -i perekop
```

## Проверка правил маркировки и проксирования

```shell
nft list ruleset | grep -B3 mark
```

Вы должны увидеть цепочки `mangle`, `mangle_output` и `proxy` в таблице `PerekopTable`. Ключевые моменты:

- **Счётчики (`counter packets`)** для `ip daddr 198.18.0.0/15` в `mangle` должны быть **ненулевыми**. Если нули — трафик от клиентов не доходит (DNS или шлюз на клиенте).
- **Нет других правил с маркировкой.** «Лишние» цепочки говорят о конфликте (например, неудалённый GetDomains, `vpn-client` на GL.iNet).
- **Сумма пакетов** в `mangle` и `mangle_output` должна примерно соответствовать `proxy`. Существенно меньше в `proxy` — конфликты nftables или «простои» Xray.

## Проверка VPN-интерфейса

```shell
curl -v --interface wg0 ifconfig.me
# замените wg0 на имя вашего интерфейса
```

Если туннель работает, вернётся внешний IP VPN-сервера. Зависание/ошибка — проблема в туннеле.

## Проверка прокси

Совместимость со всеми прокси-клиентами гарантировать невозможно.

- Работает в NekoBox, но не в Perekop → экспортируйте из NekoBox в JSON и вставьте как `Outbound Configuration`.
- Протестируйте Perekop с 2–3 заведомо рабочими ссылками. Если с ними работает, а с вашей — нет, проблема в вашей ссылке.
- Поддерживаются `vless://` и `ss://`. Если ссылка заведомо рабочая — напишите в чат (см. ниже).

## Сайты детектят прокси

1. Включите **Block IPv6** (по умолчанию включено)
2. Включите **Block WebRTC** (по умолчанию включено)
3. Отключите QUIC: `disable_quic=1`
4. Отключите WebRTC в браузере (Firefox: `media.peerconnection.enabled = false`)
5. Отключите DoH/DoT в браузере
6. Проверьте IP-репутацию выходного узла

## Высокое потребление памяти / OOM

- **OOM каждые 3–5 мин:** наблюдайте в логах ядра:
  ```shell
  dmesg | grep -i "out of memory"
  ```
  и heap Xray:
  ```shell
  xray api statssys -s 127.0.0.1:10085
  # Sys: ... / Alloc: ... / NumGoroutine: ...
  ```
- По умолчанию `xray_memlimit=10` (GOMEMLIMIT), `xray_gogc=20`. Выше 10 MiB куча раздувается до ~120 МБ и ядро убивает Xray на роутерах с 256 МБ ОЗУ.
- Отключите **Enable Traffic Statistics** → снижает потребление ~вдвое (~40 МБ вместо ~80). При этом дашборд покажет N/A для трафика.
- Уменьшите количество proxy-ссылок, уберите лишние community-списки и домены.
- **Watchdog:** каждые `xray_watchdog_interval` минут (по умолчанию 30) cron проверяет heap (`xray api statssys`, fallback VmRSS) и рестартит только сервис xray при пороге (по умолчанию 50% ОЗУ, clamp 40–80 МБ). Отключается `xray_watchdog=0`. Ручная проверка:
  ```shell
  /usr/bin/perekop xray_watchdog
  crontab -l | grep perekop
  /etc/init.d/xray status
  ```

## ERR_CONNECTION_CLOSED

Обычно QUIC-блокировка. Теперь QUIC отбрасывается на уровне nft (до tproxy), браузер откатывается на TCP. Если остаётся:

- Проверьте, что `disable_quic=1`
- Очистите кэш браузера
- Попробуйте другой браузер

## Проверка конфигурации

В LuCI → Services → Perekop → Diagnostics есть кнопки проверки:

- DNS availability
- FakeIP
- nft rules
- Xray status

## Не хватает места на overlay

```shell
df -h /overlay
opkg list-installed | grep -E "sing-box|xray|perekop"
df /overlay | awk 'NR==2 {print $4}'
```

Ошибка вида `Only have 0kb available on filesystem /overlay`:

- Удалите старые бэкапы бинарников: `rm /usr/bin/xray.*.bak /usr/bin/xray.opkg.bak`
- Удалите временные файлы: `rm -rf /tmp/perekop /tmp/xray-latest.zip`
- Если `sing-box` не используется — `opkg remove sing-box` (38 МБ)
- Для установки конкретного пакета: `opkg install <pkg> --force-space` (только если места реально достаточно)

## Обращение за помощью

Приложите одним сообщением:

1. Скриншот вкладки «Диагностика» (с проблемного устройства, без обрезки).
2. Результат Global Check (`/usr/bin/perekop global_check` → .txt; чувствительные данные скрыты).
3. Логи (`logread` или «Посмотреть логи» в диагностике → .txt).
4. Лог установки/обновления (если проблема с установкой).
