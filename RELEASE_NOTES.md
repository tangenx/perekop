## Perekop v1.1.0

### Исправления

- Xray падал по OOM каждые 3–5 минут на роутерах с 256 МБ ОЗУ: при `GOMEMLIMIT=25MiB` Go-куча раздувалась до ~120 МБ `Sys` (Alloc 22–34 МБ, тысячи горутин) на короткоживущих соединениях через tproxy+sniffing. Теперь по умолчанию `GOMEMLIMIT=10MiB` и `GOGC=20` (`xray_memlimit`, `xray_gogc` в настройках), `Sys` остаётся ~20 МБ, RSS ~30 МБ
- В дашборде при подписке вместо названий серверов показывались имена аутбаундов вида `main-1-out`. Бэкенд `get_proxies` теперь отдаёт `names` из фрагмента ссылки, фронт мапится на них
- Добавлена настройка «Xray memory watchdog» (включена по умолчанию): cron проверяет heap Xray (`xray api statssys`, fallback VmRSS) и рестартит только сервис xray при превышении порога (по умолчанию 50% ОЗУ, clamp 40–80 МБ, интервал 30 мин). Настройки: `xray_watchdog`, `xray_watchdog_interval`, `xray_watchdog_rss_mb`
- FakeDNS-пул уменьшен с 65535 до 4096: большой пул удерживал ~10–16 МБ живых объектов во время burst'ов
- Идемпотентная настройка dnsmasq на reload (раньше reload не трогал dhcp, dnsmasq-конфигурация могла остаться стоковой навсегда)
- Подписка, добавленная позже, теперь дотягивает список перед сборкой конфига; скачивание подписки обходит резолвер через `--resolve` (Quad9 может не резолвить хост подписки)

### Исправления

- Списки сообщества применяли только geosite. Подсети из этих списков помечались nft, но не попадали в правила маршрутизации Xray, поэтому трафик к ним выходил напрямую (в логах `tproxy-in -> direct-out`). Теперь скачанный список сохраняется и его подсети маршрутизируются через прокси-группу наравне с доменами
- Загрузка списков через прокси/VPN завершалась ошибкой 503: `wget` получал адрес SOCKS5-порта, но отправлял HTTP-запрос. Теперь загрузка идёт через `curl --socks5-hostname`
- Клиенты могли обходить туннель по IPv6 и показывать сайтам свой реальный адрес. Добавлена настройка «Block IPv6» (включена по умолчанию): IPv6-трафик от исходных интерфейсов отбрасывается в цепочке `forward`
- QUIC (HTTP/3) блокировался правилом маршрутизации Xray, которое отбрасывало UDP 443 для помеченного трафика. Это ломало соединения к сайтам за Cloudflare (ERR_CONNECTION_CLOSED), потому что браузер получал сброс соединения вместо чистого отказа и не откатывался на TCP. Теперь QUIC отбрасывается на уровне nft (до tproxy), как в оригинальном podkop, что даёт чистый отказ и корректный откат на TCP
- Браузеры утекали реальный IP через WebRTC STUN даже при работающем прокси: STUN-сервер не входит в списки доменов, поэтому его трафик шёл напрямую и браузер узнавал адрес провайдера. Добавлена настройка «Block WebRTC» (включена по умолчанию): STUN-трафик (UDP 3478 и 19302-19309) от исходных интерфейсов отбрасывается. Отключайте только если нужны видеозвонки в браузере
- Добавлена настройка «Enable Traffic Statistics» (включена по умолчанию). Отключение сбора статистики снижает потребление памяти примерно вдвое (с ~80 до ~40 МБ RSS), что критично для устройств с 128 МБ ОЗУ. При отключении дашборд показывает N/A для трафика

### Новое

- Кнопка «Test latency» в группе URLTest теперь закрепляет самый быстрый измеренный сервер и показывает его в плитке «Auto». Ручной выбор сервера не перекрывается тестом, а выбор «Auto» снимает закрепление теста
